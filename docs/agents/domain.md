# 领域文档

工程类 skill 探索代码库时应如何消费本仓库的领域文档。

## 探索之前先读

- 仓库根目录的 **`CONTEXT.md`**；或
- 若存在根目录 **`CONTEXT-MAP.md`**：它指向每个上下文各自的 `CONTEXT.md`，读与当前主题相关的那些。
- **`docs/adr/`**：读与即将改动区域相关的 ADR。

这些文件不存在时**静默继续**：不要指出缺失，也不要建议提前创建。`/domain-modeling`（经 `/grill-with-docs`、`/improve-codebase-architecture` 到达）会在术语或决策真正确定时惰性创建。

## 文件结构

本仓库为单上下文：

```
/
├── CONTEXT.md
├── docs/adr/
└── src/
```

## 使用术语表的词汇

输出提到领域概念时（工单标题、重构提案、假设、测试名），使用 `CONTEXT.md` 中定义的术语，不要漂移到术语表明确避开的同义词。

需要的概念不在术语表中是信号：要么你在发明项目不使用的语言（重新考虑），要么存在真实缺口（记下来交给 `/domain-modeling`）。

## 标记 ADR 冲突

输出与既有 ADR 矛盾时明确暴露，而非静默覆盖：

> _与 ADR-0007 冲突，但值得重新讨论，因为……_
